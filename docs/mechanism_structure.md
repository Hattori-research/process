# 機構の構造と運動の解釈（claude.ai での推論, 2026-10-01）

CLAUDE.md の「実機」「ワイヤごとの移動方向」を補足するメモ。CAD（assembly3-Assembly.step, fiber_0-Body.step）と
2026-09-29 取得データの解析結果（analyze_wire_direction.py）を突き合わせて推論した。**解釈は仮説を含む**（末尾の「未確認」参照）。

## 1. 構造（CAD から確認した事実）

- 繊維は **12本**（30°おき、中心から半径 19.6mm、長さ 200mm）。**うち4本がワイヤ付き**（内部に箱型のアンカー、z≈147.5mm）
- ワイヤ付き繊維 = F0, F3, F6, F9（90°おき）。CAD 座標での角度: F0 = 20.4°, F3 = 110.4°, F6 = −159.6°, F9 = −69.6°
  - F番号は CAD の XY 平面で F0 から反時計回りに 30°ずつ（Fk = 20.4° + 30k）
  - 向かい合う組は F0–F6, F3–F9
  - ※ assembly3-Assembly.step は12本すべてがワイヤ付き繊維になっている（実機と異なる）。ワイヤなしの繊維は fiber_0-Body.step
- ガイド: 36個（隣り合う繊維のすきま12か所 × 3段）。高さは 30/85/130, 50/100/150, 70/115/170mm の3通りで、90°ごとに同じ並び
- ワイヤはアンカーに結び、キャップ上部の穴を通してモータで引く（押せない）
- 断面図: `docs/mechanism_cross_section.png`（z=50mm と z=147.5mm。赤＝ワイヤ付き F0/F3/F6/F9、青＝ワイヤなし、灰＝ガイド。CAD 座標で Z が繊維の軸）
  - assembly3-Assembly.step のワイヤ付き繊維4本と、fiber_0-Body.step（ワイヤなし繊維）を 30°ずつ回転して8か所に置いて組み直したもの（実機どおりの配置）

## 2. キラリティ（鏡に映すと重ならない向き）

- ワイヤ付き繊維の断面は旗形（P字状）、ワイヤなし繊維は上辺の傾いたT字で、**12本とも同じ回転方向を向く**（断面全体が風車状）
- ガイドも、片側の繊維を包んで隣の繊維へ張り出す向きが**全周でそろっている**
- 引いた繊維と中心軸を含む面に対して鏡面対称な機構なら、1本引いたときのねじれの向きは定まらない（ワイヤで逆になる）。
  本機構はこの対称性を持たないので、**軸方向の縮み・繊維の滑りが常に同じ向きのねじれに変わりうる**
- これはユーグレナ自体がキラルであることと一致しており、**ねじれ自体は設計どおりで問題ではない**（服部）

## 3. データの分解：共通成分と曲げ成分

1mm 引いたときの移動（CLAUDE.md の表）を、向かい合う組で平均と差に分けた:

| 組 | 差（2本の差）の向き（XY） | 差の大きさ [mm/mm] | 平均（共通成分）(dX, dY, dZ) |
|---|---|---|---|
| W0 と W3 | 111° | 0.97 | (−0.06, −0.44, −0.29) |
| W1 と W2 | 0° | 1.43 | (+0.09, −0.94, −0.52) |

- 2組の「差」はほぼ直交 → **十字配置のワイヤは設計どおり曲げとして働いている**
  - 注（2026-10-01 Claude Code 検算）: 表の数値は CLAUDE.md の表から再計算して一致（差は W3−W0, W2−W1、大きさは XY 成分）。2組の差のなす角は約 111° で、直交から約 21° ずれている
- 別に、**どのワイヤでも出る共通成分（−Y 向き 0.44〜0.94mm/mm、かつ上向き）**がある
- **W3 が効かないように見えるのは、W3 の +Y 向きの曲げと共通成分の −Y がほぼ打ち消し合うため**。W0 との差では +Y 側へ 0.97mm/mm 動かせており、W3 は働いている
- **W0–W3、W1–W2 がそれぞれ向かい合う**（データからの予想を服部が実機で確認, 2026-10-01）。したがって {W0, W3} と {W1, W2} は F0–F6 / F3–F9 のどちらかの組に対応する。どの W がどの F かは未確認

## 4. 位置が −Y 側に偏る理由と、学習上の含意

- 引くだけ（自然長から出発）では、どのワイヤでも共通成分の −Y が加わるため、+Y 側へは出られない。
  **これは到達可能範囲の問題なので、学習手法だけでは解消できない**（データにない領域は学習できず、指令でも到達できない）
- **予張力が効く理由**: 全ワイヤに予張力 p をかけた状態からは、各ワイヤを「引く (+v_i)」「緩める (−v_i)」の両方ができ、
  4本の ±v_i が水平面の全方向を張る → その状態のまわりでは全方向に動ける。腱駆動連続体ロボットの拮抗予張力と同じ考え方
  - `pretension` モード（10±10mm）はこの意味で有効。`random_multi` は緩める動きを含むが、自然長付近では 0 より緩められないので偏りは残りやすい
- 実装上の提案:
  1. **基準姿勢（原点）を予張力状態に置く**。目標点・相対座標・エンコーダ基準を予張力状態基準にする（自然長基準のままだと基準点が到達範囲の端になる）
     - 注（2026-10-01）: **提案のみで未採用**。現在の決定は「原点 = 自然状態のマーカ先端」（CLAUDE.md、2026-09-28 決定）
  2. データ取得は予張力のまわり（pretension モード）を中心にし、NARX に「緩める」動きを学習させる
  3. ワイヤ4本で位置3次元なので1自由度余る（全体の張り具合）。この冗長性が逆モデルの多対一の原因の一つ。
     コントローラの損失に「合計張力を基準値に保つ」項を足すか、出力を「共通1＋曲げ用の成分」の座標で表すと解が一意に近づく
  4. 修繕後データで、予張力状態のまわりの局所的な関係 Δx ≈ J Δw（J: 3×4）を最小二乗で求め、J の条件数で全方向に動けるかを確認する
